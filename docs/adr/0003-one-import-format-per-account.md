# Each Account is bound to one import format

Each Account is bound to exactly one import format (CAMT.053 or one specific bank CSV layout), and that format defines its Fingerprint. A Transaction's Fingerprint is the bank's own reference when the format provides one (`AcctSvcrRef` for CAMT.053, `No de transaction` for UBS CSV). Otherwise it is a hash of the Account, booking date, amount and normalised description, plus an occurrence index. About 12% of BCGE CAMT entries have no reference, so one Account can hold both kinds of Fingerprint. Fingerprints from different formats can't be matched reliably, because the same bank writes different references and descriptions into each format, so mixing formats on one Account would silently duplicate Transactions. We considered a fingerprint built only from fields every format shares (date, amount, occurrence index), and rejected it as weaker than one stable format. Once an Account has Transactions, its format can't be changed. One bank entry becomes one Transaction, even when the bank bundles several payment details into it.
