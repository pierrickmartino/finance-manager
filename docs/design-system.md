# Design system

The app's look: light ink and one cyan accent on a deep navy page, Inter for everything read and operated, Inter Tight for display, and small corners. It is **dark only** (ADR-0017): every page, the sign-in page included, keeps these colours whatever the system theme, and the document declares a dark colour scheme so native controls and scrollbars are dark too. There is no light theme and no toggle, so every token has one value.

Two files hold it, and a page takes its look from them:

- `src/app/globals.css`: the **tokens** (the `@theme` block), so every colour, both fonts and the corner radii are Tailwind utilities (`bg-paper`, `text-ink`, `border-rule`, `font-display`, `rounded-xl`…). Values live there only; the font files are loaded with `next/font` in `src/app/layout.tsx`.
- `src/components/surface.ts`: the **primitives**, class names that say what an element is (a page title, a primary button, a card).

Style with tokens and primitives, so a change to the look is a one-place edit. When a page needs something neither covers, add a token or primitive first, then use it. Two tests guard the colours: `src/lib/color/design-tokens.test.ts` checks every token text pair, each heatmap level's number and white text on the ramp's deep steps for AA from the values in `globals.css`, and that every ramp step stays clearly apart from the accent; `e2e/design-system.spec.ts` checks real pages declare a dark colour scheme and stay dark under a light system theme, that their text and focus outline pass AA on what is computed behind them (and on the opaque fallback surface), that containers are glass and turn opaque under the fallback, and that every tile of the Dashboard and Analytics glows.

## Tokens

| Token | Role |
| --- | --- |
| `paper` | Page background: the deep navy every page, and the bar, sits on, with the page glow fixed behind the content. |
| `surface` | Cards, inputs, menus: anything that sits on the page, a step lighter than it. Containers show it as glass (translucent); it is also the opaque fallback surface. |
| `sunken` | Hover, selected rows, tracks, quiet fills; the quiet notice's glass. |
| `rule` / `rule-strong` | Dividers and card borders / control borders. |
| `ink` | Text (near-white), and the primary button's fill. `ink-hover` is the primary button's hover. |
| `ink-soft` | Tertiary headings and quiet controls. |
| `muted` | Secondary text: labels, hints, metadata. The lightest colour for words. |
| `faint` | Placeholders, disabled and decorative marks only (too light for words). |
| `accent` | Cyan fill: the brand dot, the accent button's hover and marks such as the Net worth card's Capital diamonds. |
| `accent-ink` | Cyan for text, links, the focus ring and controls such as an on toggle, and the accent button's fill; AA on `paper`, `surface`, `sunken` and `accent-tint`. |
| `accent-tint` | Selected navigation (the bar's current pill, the drawer's current link), highlighted rows. |
| `ramp-1` … `ramp-5` | The ramp: five flat steps from sky blue (`ramp-1`) through blue to violet (`ramp-5`), each clearly apart from the cyan accent (at least ΔE 15, CIEDE2000, from `accent` and `accent-ink`, checked by `design-tokens.test.ts`) so a ramp mark never reads as a state. The marks of the Dashboard's and Analytics' cards, the heatmap, the Net worth bands and the sparklines (see Rules), with `bg-hatch` for the period a card points out. `bg-ramp-*` is a flat step; the ramp's gradients (sky blue → blue → violet, fills only) live in `RAMP_FILLS` (`src/lib/color/ramp-fills.ts`, see Rules). `insight` (the insight tile's violet, as glass: `INSIGHT_TILE_CLASS`) and `bg-spotlight` / `bg-spotlight-strong` (Recent activity's spotlight and its hover) are deep, flat steps of the ramp mixed into `surface`, dark enough for white text. |
| `on-ramp` | White: text, outlines and translucent fills of the bar's controls (`text-on-ramp/75`, `ring-on-ramp/40`), and text on the insight tile and the spotlight. |
| `on-ink` | Navy text on an `ink` fill (it reads `paper`, so the value lives once): a selected list item (Categories, Rules, Tags, Payees) and the current Dashboard tab. A button on `ink` takes `PRIMARY_BUTTON_CLASS` instead. |
| `positive`, `negative`, `warning`, `info` (+ `-tint`, `warning-rule`) | Meaning only: income and success, expense and errors, attention, neutral status. Never decoration. `positive` is a yellowish green, clear of teal and cyan, so a chart colour never reads as good news; `warning` is an orange kept well apart from the cyan accent so attention never reads as a link or a selection. All pass AA on `surface` and on their tints. |

Type: `font-display` (Inter Tight) for page titles, section titles and headline amounts; the default sans (Inter) for everything else. Amounts that line up use `tabular-nums`.

Corners: the radius scale itself is small (`rounded-md` 6px, `rounded-lg`/`xl`/`2xl` 8px, `rounded-3xl` 10px). Buttons, pills and avatars use `rounded-lg`, badges `rounded-md`. Keep `rounded-full` for things that are round by nature: dots, toggles, progress tracks.

Motion: route navigations animate with View Transitions (ADR-0012). `--motion-duration-nav` (250ms) and `--motion-ease-nav` (`cubic-bezier(0.16, 1, 0.3, 1)`) are plain CSS variables on `:root` in `globals.css`, not utilities, and are the defaults of every `::view-transition-group/old/new(*)`. A page names the elements that move with React's `<ViewTransition>`; an override of the duration or easing uses these tokens. Under reduced motion every view transition is instant: one global rule sets `animation: none` on its pseudo-elements (checked by `e2e/view-transitions.spec.ts`). Any other animation or transform transition carries `motion-safe:` or `motion-reduce:animate-none` / `motion-reduce:transition-none` in the same class string; colour and opacity transitions are exempt.

Breakpoints: the **page** lays out by the window, with Tailwind's screen breakpoints (`sm` 40rem, `md` 48rem, `lg` 64rem): the board's 12 columns from `lg` and one column below it, Analytics' three columns, and a board Card filling its cell (`lg:h-full`). **Inside a Widget's Card** everything lays out by the Card's own width instead, with Tailwind's default container breakpoints on `WIDGET_CARD_CLASS` (`@2xs` 18rem, `@xs` 20rem, `@sm` 24rem, `@md` 28rem, `@2xl` 42rem; no custom container tokens until a Card needs a width they lack), so the same Card reads the same wherever it is equally wide. Width changes only layout and text size, never the Card's mark or which items it shows. A ring Card's list sits below the ring under `@md` and beside it from `@md`. A Card's lead figure is `text-xl` under `@md` and `text-3xl` from `@md`, so Analytics' third-width sections and narrow board Cards get the smaller lead from their width, not from a flag. A Card's facts are one column below `@2xs`, two from `@2xs` and three from `@2xl`. A ranking's tick meter (decorative, hidden from assistive technology) is hidden below `@2xs`, its percent staying beside each item. A bars Card's bars sit closer together below `@xs`. Dots, the heatmap, a line flow's areas and the Net worth line do not change with width.

## The app shell

Signed in, the app runs full width and dense. The page is the navy, and one slim bar (48px) on it carries the brand, the most used pages as pills (every other page under More), the quick actions, settings and sign out; there is no greeting or breadcrumb, as the page's own title says where you are. The page's content follows right below the bar, with no panel or band of its own. The current page's pill is marked in the accent (`accent-tint` under `accent-ink`), as the drawer marks its current link. Below `lg` the pills give way to a drawer, a glass panel (`GLASS_CLASS`) over the dimmed, blurred page; under the opaque fallback it is opaque and nothing blurs. The bar's main action (Review unclassified) takes the primary button's look. The notifications bell sits first in the bar's right-hand group at every width; its popover (`POPOVER_CLASS`) lists the Attention items, each with a `BADGE_CLASS` badge in its tone, and on a phone spans the screen within the 16px gutters. While any item is unread the bell carries a small `accent` dot ringed in `paper` (news, not a severity: severity is the badges' job), and the popover marks the items that were unread with the same dot in their row, in `ink` and medium weight. The bar's controls take their look from `src/components/app-shell/bar-styles.ts`. Titles stay compact for the same reason (`PAGE_TITLE_CLASS` 24px, `SECTION_TITLE_CLASS` 18px, `HEADLINE_AMOUNT_CLASS` 30px): the page's content, not its heading, comes first.

## Rules

- **One accent.** Cyan marks what is selected, focused or the point of a chart (as `accent-ink` for text, rings and controls). Amber is no longer an accent anywhere. Status colours carry meaning and stay apart from it. The ramp is atmosphere, not a second accent: it never marks a state, and it appears only in the cards of the Dashboard and Analytics (their marks, the insight tile, Recent activity's spotlight) and the page and tile glows. Its steps are kept clearly apart from the cyan accent, so the marks drawn in `ramp-1` (a sparkline's line, the heatmap's running-period outline) never read as selected.
- **Display with restraint.** Inter Tight for titles and headline amounts only; labels, tables and controls stay in Inter.
- **Words in sentence case.** Labels and group names read as plain words, without letter-spaced capitals.
- **Charts.** Categorical series (several Categories or Accounts on one bars, line, area or Donut Widget, and their legends) use `CHART_PALETTE` (`src/app/dashboards/chart-palette.ts`), eight hues separate from the ramp: neon first (cyan, blue, teal, violet), then warm hues (amber, magenta, pink, coral) so neighbours never collide; a ninth series folds into "Other". Every adjacent pair, the last against the first included, clears ΔE 8 (CIEDE2000) under simulated protan, deutan and tritan vision, and every hue reaches 3:1 against `surface`; `src/lib/color/design-tokens.test.ts` proves both, so re-run it after any change to the order or a hue. No series is the accent, and text never takes a series colour: chart text and gridlines use `muted` and `rule`, on `surface`. Other categorical colours read from it too, never copied hex values: a Transaction detail's Split lines and their allocation bar take `lineColor` (`src/app/transactions/[id]/allocation-bar.tsx`), so a palette change reaches them. The Dashboard's cards (`src/app/dashboards/(dashboard)/[id]/overview/`) draw in the ramp, continuing the page's atmosphere into the cards (ADR-0009, ADR-0017), and draw every section of Analytics too, so the two pages read alike. **Gradients in fills only**: the ramp's sky blue → blue → violet gradients (`RAMP_FILLS` in `src/lib/color/ramp-fills.ts`, drawn by `RampGradient` in SVG and `cssGradient` in HTML) fill the sparklines, the Net worth card's bands and the area under its line, a trend card's bars and the overview's Net worth tile, and nothing else: never text, a line, a stroke or an outline, never the heatmap (a stepped single hue) and never a Capital diamond (the accent). A gradient is atmosphere and never marks a state: hatching, dashed partial segments and the running period's outline still say "partial", and the accent still marks the point. Text that sits on a gradient (the Net worth tile's words, the Net worth plot's value label on its `ink` plate) is listed in `TEXT_ON_RAMP_FILLS` and passes AA at every step of it (`design-tokens.test.ts`). A trend card's latest bar is hatched, the running period's when its range reaches today. A table Widget's card is a heatmap (`HeatmapGrid` in `marks.tsx`): six stepped shades of `ramp-3` mixed into `surface` (`HEAT_HUE` and `HEAT_LEVELS` in `src/lib/reporting/heatmap.ts`), the largest the brightest, stepped so each number passes AA: `ink` on the quiet five, navy `paper` on the full hue (checked by `design-tokens.test.ts`); a cell with no value is a `muted` dash; the running period is outlined dashed in `ramp-1` just outside its cells, on the card. A trend card's other bars are the ramp's gradient, translucent, violet at the foot to sky blue at the top, and a bar below zero is `negative`, translucent. Rows that form a tree (Analytics' Categories per interval) keep their order instead of ranking by size: a quiet heading per Category group type with its total, each group a `sunken` band of plain bold subtotals, its Categories indented under a `rule-strong` tree line and shaded against the largest Category cell of their own type (`toTreeHeatmap`), each named in full ("Income › Salary") for assistive technology. A line flow's card (a line Widget whose two columns are its income and expense; `overview/flow-areas.tsx`) draws two overlapping areas, Income in front of Expense, each a ramp gradient fading to nothing at its foot (`RAMP_FILLS.incomeArea` in `ramp-1`, `RAMP_FILLS.expenseArea` in `ramp-4`) under its flat 2px line in the same step, over a `rule-strong` zero line, with a legend of both; each series is one path however many points it has. A segment reaching a partial point is dashed, and that point's dots are hollow. The plot is one focusable control: hovering, or the arrow keys, picks a point and draws a `rule-strong` crosshair, a dot on each line ringed in `surface` and its figures (Income, Expense, Kept) in `ink` and `muted` on a solid `surface` plate, hung on whichever side of the crosshair keeps it inside the plot, Income and Expense each a link to its column's Drill-down through that point. A click opens the Drill-down of the area under the pointer (above the lower line the higher series, below it the lower); Enter moves focus to the figures' links; on a touch screen the first tap shows the figures, which take taps, and the second opens the area under it. A bars flow keeps its dot matrix (`ramp-1` in, `ramp-4` out). A Donut Widget's card is a ring (`overview/ring.tsx`): its parts in the ramp, `ramp-1` for the largest, "Other" last in `rule-strong`, a part whose sign goes against the total (a refund among expenses) outlined in dashed `negative`, the total in the hole; the list below it on a narrow Card and beside it from `@md` (see Breakpoints) carries every value as text. A Net worth card (`overview/net-worth-mark.tsx`) stacks a band per Account kind above zero, each a gradient of two neighbouring steps, lighter at its top (current `ramp-1` → `ramp-2`, savings `ramp-3` → `ramp-4`, 3a `ramp-4` → `ramp-5`, so touching bands stay two steps apart), loans in translucent `negative` below it and drawn as steps, over a faint sky-blue gradient under the Net worth line and under the line and its points in flat near-white `ink`; its facts carry each kind's share as text. Each capital movement on it is a small diamond in `accent` outlined in `paper`, placed along the line at its date: the point of the chart, so the one accent, and the only accent-coloured mark on the card (no ramp step comes near its cyan); each opens its Transaction, and the card's "Capital movements" count opens their Transactions list. The latest point's value label hangs inside the plot (ending at its dot on the right half). The overview's "Your net worth today" carries a sparkline beside its amount (under it below `sm`; `overview/headline-trend.tsx`): the last 24 months of Net worth in a flat `ramp-1` line over the ramp's gradient (sky blue at the line, violet at its foot), scaled to its own low and high, the latest point a dot, no bands, no Capital markers and no peak. Under it, chips on `sunken` give the change over 1M, 1Y and 2Y (since the month-end 1, 12 and 24 months before today, a chip left out when the line does not reach that far back), in `positive` with ↗ or `negative` with ↘, each opening the Accounts as of that month-end. On Analytics the line runs over the Period instead (its start, each Interval end, today; the start labelled with the Period's first day) and one "Period" chip in their place gives the change since the start of that day, opening the Accounts as of the day before. Edit mode draws the same cards, each with a toolbar of `GHOST_BUTTON_CLASS` actions; where a dragged or resized card will land is `accent-tint` with a dashed `accent-ink` outline (the react-grid-layout overrides at the end of `globals.css`).
- **Key figures.** Analytics opens with four `TILE_CLASS` tiles (`src/app/analytics/key-figures.tsx`): Net worth, Income, Expense and Profit, in one row from `lg` up and 2×2 below, never one column. Each tile is its label, a `muted` caption saying when it stands ("Today", or the Period: its preset's name, "Last 90 days", or "1 Jan 2024 – today" for a preset cut to the first Transaction), its amount in `TILE_AMOUNT_CLASS` (in `negative` below zero) opening what is behind it, then its change line, its sparkline at the tile's foot, and the unconverted note in `warning` when its own figure leaves something out. The change line (`key-figure-change.tsx`) reads "↗ +CHF 500 · +25.0% vs 1–22 Oct": the arrow and signs of the overview's chips, in `positive` when the change is good for the figure and `negative` when bad (more Expense is never green), `muted` and → when unchanged, the dates in `muted`; the whole line is one link, said in words for assistive technology. The sparkline draws as the overview's (`SparklineSvg` and `SparklineDot` in `src/components/sparkline-mark.tsx`, shared with `headline-trend.tsx`): flat `ramp-1` line and dots over the ramp's gradient fill, scaled to its own low and high; a partial current Interval is a dashed last segment ending in a hollow dot, a complete one a solid dot, and a first Interval cut short at the Period's start (ADR-0016) a dashed first segment. It is decorative (`aria-hidden`): the tile says its values as text. Expense's tile (`TILE_LOOKS` in `key-figures.tsx`) differs in three ways: its caption sits top right, beside its label (wrapping under it when the tile is too narrow); its change line shows the % alone ("↗ +25.0% vs 1–22 Oct"), the amount only when there is no %, while its spoken name still gives both; and its sparkline curves through its points (a monotone curve, `figureSparkline(…, { isSmooth: true })`, which never overshoots a peak or a trough) instead of joining them straight, its partial segments still dashed.
- **Profit and loss.** Analytics' statement of the Period (`src/app/analytics/profit-and-loss.tsx`), in a `TILE_CLASS` section two thirds wide beside Net cash flow from `lg` up, just before Profit per interval: a two-column table, each row's label then its amount (`tabular-nums`, in `negative` below zero, Expense positive) opening what is behind it. Quiet rows sit under a `rule` line; Profit and Net cash flow, which close a part of the statement, are `font-semibold`, Profit under a `rule-strong` line and Net cash flow highlighted in `accent-tint` at the foot (`negative` and `warning` pass AA on it, `design-tokens.test.ts`). A row with Transactions left out carries the unconverted note in `warning` under its label. When the Account data reaches back to the Comparison period, a third column, headed "Period" and "Comparison period" in `muted`, gives each row's amount over the Comparison period with the Key figures' change line under it (`key-figure-change.tsx`): `positive` or `negative` as the change is good or bad for the row, Capital and Unclassified always `muted` (neither good nor bad); the line wraps its dates under its figures on a phone, so the three columns fit a narrow screen (`positive` and `muted` pass AA on `accent-tint` too).
- **Glass.** Containers only: cards, lists, detail panels, the Dashboard's and Analytics' tiles (the insight tile included, in its violet), popovers and menus, the mobile drawer, notices and the Bulk edit dock are glass (`GLASS_CLASS` or a `glass-*` fill: translucent, blurring the page, in a thin luminous border). Inputs, table rows, badges and buttons stay solid; the Transactions list's rows carry their own `surface` fill so the dense list stays crisp. Only tiles (`TILE_CLASS`) carry the inner glow, so the cards read for insight stand out from working lists. Behind everything, the page glow (`--page-glow` on `body::before` in `globals.css`) draws two large, very soft radial glows from the ramp, `ramp-1` at the top right and `ramp-5` at the bottom left (atmosphere, so never the accent), fixed so they never move on scroll and never animated. A fixed view inside a glass container is held to that container by its blur, so a full-screen view is drawn on the page instead (the pivot table portals to `<body>`).
- **Reduced transparency.** Under `prefers-reduced-transparency: reduce`, or where `backdrop-filter` is unsupported, every container's fill is opaque, nothing blurs and the page glow is not drawn. One global rule in `globals.css` does it, like reduced motion's, by resetting `--glass-opacity`, `--glass-blur` and `--page-glow`. AA is measured against this opaque fallback, the conservative reference, since what shows through glass varies.
- **Focus.** Every interactive element shows the global cyan `accent-ink` outline from `globals.css`, which passes on the page, cards and the dock; keep it visible.
- **Kept on purpose.** A few things look like exceptions and are not: the pivot table's full-screen view portals to `<body>`, because a blurred (glass) parent holds a `fixed` child to itself instead of the screen; chart legends and their labels are in `muted`, like all chart text, never in a series colour; the overview's Net worth tile carries a ramp gradient (`RAMP_FILLS.netWorthTile`) as a container fill behind its text, the one gradient text sits on, faint enough that every text on it passes AA at every step (`TEXT_ON_RAMP_FILLS`, and measured in the browser on the opaque fallback); Recent activity's spotlight darkens on hover to a flat, deeper step (`bg-spotlight-strong`) rather than a gradient, so its white text keeps AA; and a missing value is a `muted` "—", never `faint`, so it still reads.
